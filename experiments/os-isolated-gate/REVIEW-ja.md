# OS分離・直接API迂回の模擬実験（未採択）

PR #11とは別の実験ディレクトリーと専用CIを追加する。現行v1.2、既存検証器、
既存ゲート、仕様案、DOC-SYNC、K3のファイルは変更しない。正式番号・適用版は未決定。
文書・実装の公開は規範の採択や本番利用の承認を意味しない。

各役割を異なる非root UIDとコンテナーに置く。役割ごとの鍵は専用の読み取り専用
ボリュームだけに置き、エージェントへ他の役割の鍵をマウントしない。
別UIDのファイルへのアクセス拒否は、秘密を含まない共有試験ファイルでも実測する。
ネットワークはエージェント→ゲート、ゲート→記録先、ゲート→模擬APIに分ける。

Linux Docker上の16ケースには、正常な実行、直接IP指定によるAPI・記録先への
接続拒否、記録先停止時の新規操作拒否、再起動後の証拠保持、代理転送・CONNECTの
拒否を含む。追加の12単体試験は制御・通信・結果集約の回帰試験であり、OS実測とは別。

比較試験では、管理側がエージェントをAPIのネットワークへ接続する。
認証のあるAPIは403で拒否する一方、意図的に無認証としたAPIには直接操作が成立する。
この場合の「迂回阻止の保証」は偽として記録する。16ケースの期待一致を、
すべての構成で迂回を阻止したという意味に読み替えない。

実際に生成された署名付き証拠を既存検証器へ渡す。現行モードは充足性を判定せず、
実験モードのみ別項目で判定する。試験鍵による受領証は独立した時刻証明ではない。

Docker権限を持つ管理者・ホスト・カーネル・ゲート・記録先・APIは信頼対象。
コンテナーはカーネルを共有し、カーネル攻撃や管理者権限への耐性は立証しない。
実測対象は記載されたIPv4経路のみ。IPv6、ホスト側サービス、外部通信の全面遮断、
本番環境の別経路・鍵管理などは未検証。独立した第三者による再現も未確立。

再現コマンド、16ケースの個別条件、信頼境界は README.md を参照。
実行記録は results/ に保存する。Macでの単体試験成功をLinuxでの実測と混同しない。
