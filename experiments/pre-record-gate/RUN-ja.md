## 実行

このディレクトリでPython 3.12または3.14の仮想環境を作り、依存関係を準備します。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m record_gate run-suite
```

一つのコマンドで模擬サービスを起動し、15シナリオを実行・期待値と比較して終了します。
PR #10の合成14ケースとは別の15ケースです。`generated/summary.json` に差分を残します。
追加の回帰試験と、書き出した証拠のオフライン再検証は次のとおりです。

```sh
.venv/bin/python -W error::ResourceWarning -m unittest discover -s tests -v
.venv/bin/python -m record_gate verify-exports --output generated
```

## 判定を分ける

| 項目 | 意味 |
| --- | --- |
| ゲートの `blocked` / `denied` | 永続化または認証・認可・結び付けを確認できず送信しなかった |
| ゲートの `result_unknown` | 送信・結果・結果保存を確定できず、再送せず照合が必要 |
| ゲートの `confirmed_success` | 模擬APIの正しい受領証を検証し、結果を永続化できた |
| 検証器の暗号学的整合性 | 提示された署名、ハッシュ、結び付け等の検証 |
| 実験モードの充足性 | 宣言した証拠提出要件について充足・不充足・不明を評価 |

事前記録だけでは実行成功になりません。応答が失われた後も同じ操作を無条件再送しません。
結果照会で見つからなかったことも「実行されなかった」とは断定しません。
結果保存が失敗した場合は、先に保存した送信意図が未解決状態の根拠として残ります。
保存先を修復した後、読み取り専用の照会で署名済み結果を回収できます。
保存済み操作IDを変えて再実行することは、この回復手順に含めません。

## 確認範囲

- 記録先停止、事前記録の応答消失、送信意図の保存障害ではAPI送信ゼロ。
- 事前記録後／送信意図保存後のプロセス強制終了で記録が残り、成功にはしない。
- 模擬APIが保存後に接続を切断すると結果不明を保持し、再送せず照会で回復。
- 対象・引数の変更、主体・委任・承認の偽装・失効・期限切れ・対象外を拒否。
- 自己申告だけの直接呼び出し、エージェント鍵による直接署名を拒否。
- 意図的に認証を外した模擬APIでは迂回が成功し、保証不成立を明示。
- エージェント側のファイルを削除しても、別プロセス・別保存先の証拠を検証可能。

アダプターは監査署名だけでなく、記録された認証・委任・承認・失効スナップショットと、
模擬APIの受領証も実際のEd25519署名から再確認します。自己申告の署名有効フラグは使いません。
ただし、認証判断の時刻は記録された合成時刻であり、現実の有効時刻を外部が証明したものではありません。

**別プロセスでも、同じOSユーザーからの鍵・保存先の隔離は未実証です。**
認証のない直接呼び出しを拒否できたことと、実運用の迂回経路をすべて閉じたことは区別します。
同一ユーザー権限の悪意あるプロセスや管理者、鍵の流出には耐えると主張しません。
外部タイムスタンプ、独立した第三者による再現、本番運用、正式採択はいずれも未確立です。

保存障害時には対象業務も止まります。10回のローカル測定値は `generated/latency.json` に残しますが、
本番の性能保証ではありません。状態遷移、信頼する役割、復旧方法、残る制約は[英語本文](README.md)に詳記しています。
