# AI支援の変更に関する証拠の実験

**未採択の研究実験です。** 既存の[pre-record gate](../pre-record-gate/README.md)
を変更せずに利用します。VAPの規範要件、VAP/VCP適合検証器、Java4Shell修正、
本番の配備制御、第三者による実装ではありません。
[設計提案](../../proposals/ai-assisted-change-evidence/README-ja.md)では、一次資料との
対応と未実装の課題を別途説明しています。[English](README.md)

## 実際に動くもの

模擬の発見記録、パッチ、変更前の状態、環境、試験計画、試験結果、承認条件の
7つのUTF-8原文をハッシュで結び付け、マニフェストに署名します。別途与えた
方針・対象状態と比較し、必要な試験項目、結果、鮮度、試験対象との一致、条件付き
承認の記載を確認します。失敗した試験の記録でも署名は有効になりえますが、
それによって試験要件を満たしたことにはしません。

既存の模擬権限者が、このマニフェストのダイジェストを含む1件の操作を承認します。
資格・委任・承認・鍵の所持・期限・失効の確認と、実行前の記録、実行意図、
署名付き受領証は既存コードを再利用します。
**実行先が行うのはダイジェストを含む模擬レコードの作成だけです。パッチ適用や
実サービスの変更、試験計画の実行は行いません。** 試験結果とレビュー条件は
合成した記載です。今回の単体・統合テストが確かめるのは、証拠の結合と管理された
呼び出しの動作であり、Javaや実パッチの安全性ではありません。

記録形式は実験専用の `ai-assisted-change-evidence/0.1` です。既存ゲートの署名用
ヘルパーを、専用のkindとkey IDで利用しています。標準のEvidence Pack形式とは
主張しません。

## 判定を分ける

| 項目 | 実験内で確認すること |
| --- | --- |
| `record_integrity` | 指定された公開鍵に対して、署名と原文ハッシュが一致するか |
| `authorization_binding` | 模擬の承認が、時刻・失効状態の入力の下で当該操作を対象としているか |
| `test_evidence` | 提出された試験結果の記載が、指定の項目・鮮度・対象一致の要件を満たすか |
| `approval_conditions` | 必須条件が揃い、署名された記載上で達成済みか。緊急例外は未対応として拒否 |
| `admission` | この実験の管理された呼び出しに対する方針上の判断 |
| `mock_execution` | 模擬レコード作成の結果。応答を失った時点では不明を維持 |
| `post_change_health` | 署名された模擬観測への帰属。未提出・不明は `NOT_ESTABLISHED` |
| `rollback_evidence` | 復旧についての模擬観測。要求や受領証の欠如から完了を推定しない |
| `external_anchor` | この実験では常に `NOT_ESTABLISHED` |

安全性・適合性をまとめた「合格」は出しません。条件の `evidence_reference` は
空でないことを確認して保持しますが、参照先の取得・独立検証は行いません。
署名は、人間が実際にレビューを行ったことを証明しません。実業務の緊急例外、
本人確認、kill switch操作、実環境のロールバックは未実装です。

**強制できる範囲：** 新しい試験・条件の方針を評価するのは、この実験の
`admit()` を通る経路だけです。既存ゲート自体は新しい方針を知りません。
`bypass-companion` は、この制約を示す負の対照です。不十分な試験結果で
実験側の判断が `DENY` でも、制御側が下位ゲートを直接呼び出すと模擬書込みは
成功します。この期待どおりの結果を確認しても、迂回経路が安全という意味には
なりません。本番で迂回不能にするには、認証情報・プロセス・実行境界の連携が必要です。

## 実行

リポジトリのルートで、Python 3.12以降と既存の固定依存を使用します。

```sh
python -m pip install -r experiments/pre-record-gate/requirements.txt
python -W error::ResourceWarning -m unittest discover -s experiments/ai-assisted-change-evidence/tests -v
python experiments/ai-assisted-change-evidence/run.py run-suite \
  --output experiments/ai-assisted-change-evidence/generated/run-001
```

`acceptance.json` の **17ケース**を実行します。ローカルのHTTP模擬サービスとSQLiteを
一時起動し、既存ゲートの証拠も検証して、新しい出力ディレクトリに保存します。
既存ディレクトリは上書きしません。秘密鍵は出力しません。公開鍵と合成した時刻・
失効状態は再検証用に含みます。非ゼロ終了は実行・検証が未完了または失敗したことを示します。

出力された `summary.json` のSHA-256を別の信頼できる経路で保持し、後から
サービスを起動せずに再検証できます。

```sh
python experiments/ai-assisted-change-evidence/run.py verify-exports \
  --output experiments/ai-assisted-change-evidence/generated/run-001 \
  --expected-summary-sha256 TRUSTED_SUMMARY_SHA256
```

末尾のプレースホルダーは、事前に保持した64桁の値へ置き換えます。信頼できない
受領物から計算し直した値を、その受領物の真正性の根拠にしないでください。
再検証は、空でない全ケース一覧、原文・署名・権限情報・判定の再計算に加え、
既存の `verify_bundle()` により元の実行証拠と受領証を検証します。負の対照も
所定の失敗として確認します。同一CI実行内でのハッシュ比較は再現確認であり、
独立した保管や外部時刻証明ではありません。要求・書込み件数はテスト側の観測で、
実行先のすべての動作を独立して証明するものではありません。

## 検証範囲と限界

通常経路、パッチ原文の改変、署名し直された未試験パッチ、失敗・不足・期限切れの
試験、環境不一致、未達の承認条件、未対応の例外、期限切れ・失効済み承認、別の
マニフェストへの承認、記録サービス停止、応答喪失と読取りだけの照合、復旧不明、
同一要求の再提示、下位ゲートへの迂回を対象にします。応答喪失後の照合では書込みを
再送しません。模擬書込みの成功、健全性の不良という観測、復旧不明も別々に残します。

鍵・時刻・サービスは単一ホスト上の同じテスト管理者の支配下にあります。
独立観測者、鍵の保護、信頼できるUTC、外部アンカー、特権管理者に対する保護は
ありません。対象状態の入力を実配備へ原子的に結び付けていないため、本番の状態変化や
確認時点と実行時点の競合は解消しません。発見記録の参照先は取得せず、実脆弱性の
悪用、外部スキャン、パッチ適用、復旧、kill switch操作も行いません。
署名された記載が最初から誤っている可能性は残り、観測範囲外の完全性や実試験計画の
十分性は立証しません。
