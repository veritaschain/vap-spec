# 管理された送信経路の実験：日本語ガイド

この実験は、前段の証拠評価器を実際のローカルHTTP送信につなぎます。
合成データを一度だけバイト列として読み取り、許可された内容と送信する内容を照合します。
別プロセスの受信先でもバイト数とSHA-256を計測し、実際に届いた内容を確認します。
VAP/CAPの新しい要件や、組織内のすべての送信経路を止める保証は追加しません。

## 実行

Python 3.12以降と、ローカルソケット・子プロセスを利用できるLinux環境を使います。
リポジトリのルートから実行してください。

```sh
python3 -m venv .venv-upload
.venv-upload/bin/python -m pip install -r experiments/incident-upload-pilot/requirements.txt
cd experiments/incident-upload-pilot
PILOT_NETWORK_TESTS=1 ../../.venv-upload/bin/python -W error::ResourceWarning run_tests.py --require-network
../../.venv-upload/bin/python -m upload_pilot run-suite --output generated
../../.venv-upload/bin/python -m upload_pilot verify-exports generated
```

`generated` が既に存在する場合は、新しい出力先を指定してください。
古い証拠と新しい実行結果を混ぜないため、既存ディレクトリへの上書きを拒否します。
終了コード0は、17シナリオの観測結果が期待値と一致し、保存結果の再検証まで完了した場合です。
通信できなかった試験を成功として扱いません。

## 送信前に確認する二つの条件

1. 署名・対象・規程・有効期間を検証した評価器が、実際に送るバイト列について `ALLOW` を返す。
2. その要求に対応する送信予定をローカルSQLiteに保存し、コミット確認を得る。

保存後、通信の直前にもう一度有効期間を確認します。許可後にデータが変わった場合や、保存に時間がかかり
許可が失効した場合は送信しません。送信予定の保存と実送信は別の事象として記録します。

評価器側の合成規程は `require_collector=false` とし、この実験の追加ルールとして送信前の保存を必須にしています。
実送信時刻の可用性を示すために、過去のcollector観測時刻を書き換える処理は行いません。

## 主な結果の読み方

| 結果 | 意味 |
| --- | --- |
| `BLOCKED_WITHOUT_ATTEMPT` | このゲートの呼び出しは通信処理に進まなかった |
| `RECEIPT_CONFIRMED` | 実際の受信先が署名した対象・ハッシュ・長さを検証し、その結果を保存した |
| `OUTCOME_UNKNOWN` | 応答や結果保存を確定できない。自動再送しない |
| `REPLAY_NO_SEND` | 既存の送信予定があるため、同じ要求を再送しない |
| `REQUEST_ID_CONFLICT` | 同じ要求IDが別の内容に使用されている |

受信先が保存した直後に応答を失うケースでは、ゲート側の結果は `OUTCOME_UNKNOWN` のままです。
実験の管理者は受信側の保存件数を確認できますが、その観測をゲートが受け取った応答と混同しません。
前段の評価器が出す `remote_outcome: UNKNOWN` も維持し、ローカル実験の受領確認を別項目にしています。

## 実験に含まれる故障・境界

データの差し替え、別テナント、未承認の宛先、期限切れ、記録保存の失敗、応答消失、不適合な受領証、
重複呼び出し、同時呼び出し、リダイレクト、送信予定の保存後のプロセス強制終了を扱います。
認証を意図的に外した受信先に、管理者が別経路で送信できるケースも含めています。
そのケースの成功は「迂回できることを観測した」という意味で、安全性の合格ではありません。

ローカルの制限環境ではHTTP用の4テストを明示的にスキップできますが、CIはスキップを許可しません。
実行環境と結果は [実行記録](results/README.md)、入力形式と範囲は [README](README.md) に記載しています。
保存済み結果の再検証は通信を繰り返しません。実行当時のホストや観測者の正当性を独立に証明するものでもありません。
