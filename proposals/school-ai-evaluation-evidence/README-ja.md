# 学校AIの警告と評価環境の構成を検証する証拠

**状態：参考情報としての設計提案・未採用。確認基準日：2026年11月6日。**

[English](README.md)

このメモは、学校でのAI対話が安全上の対応にどうつながるか、評価環境で宣言した
隔離と実際に観測した状態が一致するか、という二つの証拠上の課題を整理します。
新しいプロファイル、規範的なフィールド、適合性の主張、実装は導入しません。
本メモのためにGoogle連携、学校への導入、新しい隔離実験、受入試験を実施した
事実はありません。対応する事件記録と主張ごとの出典は
[サイト更新PR](https://github.com/veritaschain/vcp-site/pull/202)にあります。

## 2. 学校AIの安全上の対応に関する証拠の提案

以下は将来のアダプターの設計論点です。VAPやMAPに実装済みの要件ではなく、
識別子や名称も説明用です。

| 境界 | 結び付ける証拠 | それだけでは立証できないこと |
|---|---|---|
| 製品と管理アカウント | 利用した製品、管理アカウントの区分、有効な設定と版、管理者による変更、観測時刻 | Geminiアプリの設定が検索、個人アカウント、すべてのブラウザー経路にも適用されること |
| 入力と応答 | 相関ID、観測した入力と与えた文脈への参照、取得可能な提供者・モデル識別情報、応答と配信の観測、収集者 | 非公開の内部推論、取得できないモデルの版、表示された応答を本人が読んだ・理解したこと |
| リスク評価 | 分類器・方針の版、適用した閾値、観測した判定と不確実性、対象の入出力への結合 | 医学的診断、全リスクの確実な検知、観測していない判定 |
| 警告と対応 | 警告する・抑制する判定、送信試行、配信結果、権限のある受信者の確認、別途記録した対応 | 送信が配信を、配信が受領確認を、受領確認が有効な介入を意味すること |
| 検証と開示 | 請求権限、許された範囲、アクセス・エクスポート、墨消し、保持根拠、利用できない資料 | 子どもの会話を無制限に開示する権利や、欠けた資料が存在しなかったこと |

欠落を解釈する前に収集範囲を定義します。記録済みのリスク判定について、ある
方針が警告の最終結果を要求しているのに結果がない場合、それは未解決の欠落です。
「警告は不要だった」「子どもは安全だった」と読み替えません。適切な権限に基づく
独立した観測があれば、提供者、学校、配信サービスの記録を照合します。一人の
運用者が後から署名したエクスポートは、その運用者による過去の説明という範囲に
とどまります。

機微な本文は適切なアクセス制御の下で保存し、公開するコミットメントと分離
します。ハッシュは暗号化でも匿名化でもなく、予測しやすい文章は公開ダイジェスト
から推測できます。レビューしたコミットメントと開示の方式を使い、鍵の管理、
保持、許された消去を定め、本文が利用できない場合は欠落を記録します。未成年者の
実際の会話、診断ラベル、自傷の手順を証拠例として公開しません。記録だけでは
安全上の対応は実行されず、通知先の選択と介入には明確な運用方針と責任者が必要です。

## 3. 評価環境の構成と操作に関する証拠の提案

意図した設定、観測した設定、実際の到達性を分けます。管理者による
`isolation_enabled`という宣言だけではネットワークを試験したことになりません。

| 境界 | 結び付ける証拠 | 残る限界 |
|---|---|---|
| 評価の識別 | 実行ID、開示されていればモデル・チェックポイント、評価基盤・設定のダイジェスト、許可された対象範囲、制御者 | モデル名や署名された設定は、対象へのアクセス許可の証拠ではありません |
| 実行時の状態 | 版を付けた方針と、観測した経路・ID・所属・関連設定変更 | スナップショットは継続的な強制でも、全経路の証明でもありません |
| 到達性の観測 | 管理下の対象、プロトコル・経路、観測区間、観測者、正常稼働を確認する陽性対照 | 要求の失敗は対象の停止でも起こり得ます。未観測の経路は不明のままです |
| 操作と結果 | 試行、対象範囲、ツール呼び出し、独立したネットワーク・バックエンドの観測、取得可能な最終結果 | モデル自身の記録やHTTP応答だけでは、実行や影響の全体を立証できません |
| 変更と欠落 | 設定の変化、収集停止、観測の期限切れ、失効、再起動、事故と続報の関係 | 収集後の封印では、封印前に欠落した全事象は分かりません |

将来の試験は、明確に許可された管理下の対象だけを使います。この提案に一般の
インターネットへの探索は必要ありません。設定が変われば、前の版に結び付く観測
を無効にします。信頼できる強制機構を設ける場合でも、方針と観測の鮮度を実行に
結び付ける必要があります。時刻付きの事前確認だけでは、確認と実行の間の競合を
解消できません。

記録の改変検知、観測範囲、認可、隔離、観測した影響は別々に判定します。無許可
接続の証拠に有効な署名があるからといって、全体を成功判定にしません。設定の
不備と危険なモデル行動は両立し得ます。事象の順序と相関だけでは、科学的・法的
な因果関係は立証できません。

## 4. 既存仕様と実装の範囲

参照するのは[VAP v1.2 Draft 3](../../spec/v1.2/VAP_Framework_Specification.md)
です。導入済み、認証済みという主張ではありません。

| 既存の項目 | 関係と限界 |
|---|---|
| INT-004 / INT-004a | 必須なのは暗号学的な順序検証です。各イベントのハッシュチェーンはフレームワークでは任意で、プロファイルが必須化できます。§4.1.4のMerkleバッチアンカーは必須ですが、追加のイベントごとのチェーンは一律の必須要件ではありません。 |
| INT-006 / INT-007 | 外部アンカーとその連続性はフレームワークの要件です。本提案のアダプターでは未実装です。 |
| INT-008 / §11.1 | アンカー済みバッチの宣言範囲における、アンカー後の欠落を検知します。未計測・未収録の事象は、その存在を示す別の記録なしには検知できません。 |
| §4.2 / §4.3 / TRC-005 | 来歴と当事者間の結合は、発行者・信頼・収集範囲を明示した観測記録の検証に役立ちます。モデルの非公開の推論を読み取る機能ではありません。 |
| §4.1.5 / §6 | 暗号方式の移行に対応することは必須です。Ed25519は既定値であり、許容する唯一の方式ではありません。鍵の侵害と、信頼する鍵の確立は別の問題として残ります。 |
| §1.6 / §4.5.2 | VAP適合は法令遵守、安全性、証拠の受理を意味しません。MAPはv0.1.2 Working Draftとして登録され、リポジトリは改訂した本文が非公開であると説明しています。学校のチャットボットに採用済みの強制的統制ではありません。 |
| [Control-state evidence実験](../../experiments/control-state-evidence/README.md) | 限定した実験環境で宣言と観測を収集し、後から封印します。事前確認は強制機構ではなく、独立した外部アンカーや全経路の観測を立証していません。 |
| [OS隔離実験](../../experiments/os-isolated-gate/README.md) | 管理した構成で、特権を持つ制御者によるネットワーク所属変更で迂回が生じることも検証します。悪意あるホストや制御者への耐性を立証するものではありません。 |
| [事件から導く証拠の結合](../incident-evidence-bindings/README.md) | 要求、受領結果、開示、範囲を限定した消去証拠の区別を参照します。既存実験に本メモの学校向け処理が実装されているわけではありません。 |

## 5. 規制上の読み方と確認の優先順位

米国での提訴だけではEUの法域は確定しません。EUで評価する際は、域内との関係、
当事者の役割、意図された用途、適用日を個別に確認します。教育現場や未成年者の
利用というだけで、すべてのチャットボットがAnnex IIIの高リスクAIになるわけでは
ありません。Article 12のログと、システミックリスクを持つGPAIモデルの提供者に
対するArticle 55では、対象と適用条件が異なります。いずれもVAPを義務付けず、
特定の学校や評価者の違反をそれだけで立証するものではありません。[L1–L4]

高リスク規定の関連する適用日は2026年に改正されています。本メモは、報じられた
出来事の時点ですでにAnnex IIIのログ義務が一般に適用されていたとは仮定しません。
欧州委員会は、その日程と、移行措置の下で2025年8月から適用するGPAI規定を
区別しています。個別モデルの分類と市場投入日も別途確認する必要があります。[L5]

11月6〜13日の確認候補は、その後の裁判記録、Googleの具体的な回答・声明、製品別の展開
詳細、独立した評価の追加所見です。これは調査項目であり、その週に新法、当局の
要求、技術報告が必ず出るという予測ではありません。このメモによって監視や
自動実行の予定を作成したわけでもありません。

実装前に、証拠へのアクセス権限、収集範囲、保持、独立した観測、実際の操作を
担う機構を詰める必要があります。これらは暗号学的な記録の改変検知と分けて
評価します。
