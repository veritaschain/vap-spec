# クラウドのワークロード資格情報と証拠 — 参考提案

**位置付け：提案段階・未採択。範囲を限定したオフライン実験を伴う設計。** 確認日：**2026年11月7日 JST**。
[English](README.md) · [出典台帳](SOURCES.md)

基準はVAPリポジトリのコミット
[d97980f](https://github.com/veritaschain/vap-spec/tree/d97980f340ff9f81639daf8ffa6e02acbe1433ec)です。
以下の受入ケースは提案上の基準です。
[オフラインの合成実験](../../experiments/cloud-credential-evidence/README-ja.md)で、
CE-01〜CE-10の区別を範囲を限定して実行し、検証範囲と限界を別に記録します。
実環境へのクラウド接続や稼働中の制御は含まず、規範フィールド、プロファイル、適合性の結果を新たに定義しません。

## 動機と出典の範囲

[Microsoftの11月5日報告][ms]は、露出したアプリケーション資格情報を使ったクラウドへのアクセスを報告し、
少なくとも1件ではGitHub上の秘密情報探索からKey Vaultのデータ窃取まで5分だったとしています。
別々のAPI修正例を、1つの事件の時系列へ連結することはできません。
[Todylの継続報告][todyl]には11月6日の評価更新と、それ以前の慎重な評価が併存しています。
各記述の版、観測範囲、確度を保持します。

これらは証拠設計の動機であり、本提案には実際の事件ログや再構成結果はありません。
防御側の観測だけでは、攻撃者の非公開のモデル判断を直接取得できません。
出典に帰属するAI利用の評価と、手元で検証したクラウド操作を区別します。

## 結び付ける情報の候補

以下はアダプターのための情報の候補であり、**VAPの新しいワイヤーフィールドではありません**。
記録の整合性と由来、認証、操作の権限、観測結果、記録同士の対応を別々に評価する設計です。
矛盾と未解決の情報を残し、全体を安全とする合格判定へまとめません。
保護された元の記録と、変換後だと分かる正規化した表示を別に保持し、対応規則の版と秘匿化も記録します。
元の記録にない事実を、アダプターが補って作ることはできません。

| 情報 | レビューのために結び付ける候補 |
| --- | --- |
| IDの名前空間 | 出典の製品・スキーマとIDの種類を保持する。アプリケーションではAppId、アプリ所有テナント、テナント内のサービスプリンシパルを区別し、リソースのテナントとログ用ワークスペースも分ける。マネージドIDには固有の対応付けが必要で、存在しないアプリオブジェクトを補わない。 |
| 権限 | 正確な操作、リソース、対象API、テナント、適用する権限・方針、判断元、有効期間を結び付ける。クラウドの認証成功と、業務上その操作を許可した判断は別の問いである。 |
| 資格情報の参照 | 発行元が付けた秘密でない資格情報・鍵・トークンの識別子を、実際に記録されている場合に、その意味と欠落状態を含めて保持する。秘密情報、ベアラートークン、取得した秘密の内容は公開しない。推測した対応や推測しやすい秘密のハッシュで代用しない。 |
| 操作と結果 | APIの制御系／データ系、接続先・リソース、メソッド、版、試行ID、元の結果、利用可能な応答証拠を保持する。トークン発行、メタデータ列挙、内容取得、その後に観測した転送を区別する。 |
| 記録の対応 | 出典固有のIDと、版を特定した照合規則を保持する。クライアント相関ID、同じIP、近い時刻、同じAppIdだけでは因果関係を証明できない。曖昧な対応候補も残す。 |
| 時刻 | イベント・出典の時刻、判明している出典の利用可能時刻、収集者の受領、アラート、制御実行の時刻と時計の前提を保持する。利用可能時刻が不明なら不明のまま残し、後からの収集を以前の許可条件へ繰り上げない。 |
| 由来と範囲 | 元の記録のコミットメント、取得・検索範囲、期間、ページング・終了確認、欠落、収集者IDを結び付ける。対象の発行者・役割・テナント・リソースについての鍵の権限は、提出された証拠の外で確立する。 |
| 出典側の評価 | AI利用についての評価を述べた主体、公表・更新時刻、根拠の観測、限界を保持する。Agentというフィールド名、UserAgent文字列、操作の速さだけで攻撃者のモデル制御を証明しない。 |

### Azureアダプターで解決すべき点

[サービスプリンシパルのログ表][signin]は、**AADTenantId**、**AppOwnerTenantId**、
**ResourceOwnerTenantId**を区別し、**TenantId**はLog Analyticsのワークスペースを指します。
これらを名前空間を区別しない単一のtenant欄へまとめることはできません。同表にある資格情報・トークン識別子も、
常に値が入り、別サービスに共通して現れるとは限りません。
CreatedDateTimeとTimeGeneratedも出典上の意味を保持し、収集者が取得できた時刻や受領した時刻へ読み替えません。
[MicrosoftのIDモデル][identity]ではグローバルなアプリと各テナントのサービスプリンシパルを区別し、
マネージドIDのサービスプリンシパルには対応するアプリオブジェクトがありません。

[Key Vaultのログ説明][keyvault]では相関IDはクライアントが指定できる任意項目であり、
VaultやKeyの情報取得と、秘密情報の操作は別です。制御系APIのHTTP 200や、Key Vault向けの
トークンがあることだけでは、秘密の内容取得は確認できません。SecretGetの観測が裏付けられても、
確認できるのは出典が報告した読出しであり、全ペイロードの取得記録、外部への持出し先、その後の利用には
対応する証拠が必要です。このアダプターの推論範囲は、Microsoftの事件調査結果を変更するものではありません。

同文書は、説明対象であるStorageへのログ保存経路について、操作後に情報を利用できるまで
最大10分と記載しています。本件で測定した遅延、あらゆる取得経路の遅延、対応SLAを示すものではありません。
イベントから証拠の利用可能性までと、証拠から対応までの遅延を分けて評価します。
取得済みログに署名しても、事後の観測が予防制御になるわけではありません。

## 受入ケース案

以下はすべて仮想の合成入力を想定しています。要求する区別は提案上の基準であり、テスト結果ではありません。
ケース名は、この議論の中だけで使う識別子です。初期の設計では未実行として記録しました。
その後の合成データでの実行範囲は、[実験側の対応表](../../experiments/cloud-credential-evidence/README-ja.md#受入ケースとの対応)で説明します。

| ケース | 入力の候補 | レビューで区別すること |
| --- | --- | --- |
| CE-01 | 由来、テナント内のID、実行時点で有効な操作権限、リソース観測が一致 | 実証した操作と収集範囲に限って裏付ける。その後の利用や普遍的な完全性は推定しない。 |
| CE-02 | 認証・トークン発行は成功したが、リソースの記録や操作の許可がない。別の入力では方針による拒否が裏付けられる | 認証の証拠は保持する。アクセスや権限の証拠がなければ未解決とし、具体的な矛盾が成立する場合は残す。 |
| CE-03 | 同じAppIdが顧客2テナントに現れる。またはワークスペースのTenantIdをID側のテナントと取り違える | テナント内の主体を合併せず、別テナントへ権限を引き継がない。名前空間の対応が不明なら未解決とする。 |
| CE-04 | 署名は数学的に正しいが、その鍵の発行者・役割・テナント・リソースに対する権限が確立されていない | 署名の計算上の正当性を、信頼できる由来や記述内容の真実と区別する。 |
| CE-05 | クライアント相関ID、IP、近い時刻は一致するが、リソース・IDの結び付けが不明または矛盾する | 対応候補として保持する。共通ラベルだけで因果関係や独立にアンカーされたXREFを成立させない。 |
| CE-06 | ARMのメタデータ要求に200が返る。出典と対応付いたSecretGetイベントと比較する | メタデータ取得成功を秘密の内容取得と呼ばない。実際の操作と、取得証拠の範囲を保持する。 |
| CE-07 | 記録上のイベントは操作前だが、取得・受領は操作後、または利用可能時刻が不明 | 操作前の確認へ日時を遡らせない。裏付けがある遅延区間だけを測り、不明な時計・利用可能時刻を残す。 |
| CE-08 | 失敗した要求の後、メソッド・版・宛先を変えた試行に成功応答が返る | 各試行と正確な対応を残す。先の失敗を上書きせず、後の応答を以前の要求へ移植しない。 |
| CE-09 | ローテーションまたは1テナントの異常がないログ検索。トークンの由来、別テナント、収集期間の終了確認は不明 | 範囲付きの結果と欠落を残す。更新や記録の不在だけで、完全な封じ込めやアクセス不存在を確定しない。 |
| CE-10 | 初期の慎重な評価、後日の評価変更、またはAgent・UserAgent欄だけがある | 日付を付けた出典の評価を保持する。過去を黙って上書きせず、攻撃者の判断を直接観測した記録を作らない。 |

## 次のレビューに必要なもの

オフライン実験は、範囲を限定した版付きの対応表、合成入力、呼出側から独立に与える信頼・権限設定、
宣言した収集範囲を用意します。一致する正常対照と、結び付けを個別に変えた負例には実資格情報を使いません。
実環境への接続には、環境ごとの対応、収集、権限の設定が引き続き必要です。
対象環境の元ログの由来と利用可能性も確認が必要です。
通常のAzureログ取得物に、プロバイダーのイベント署名が付いて独立検証できるとは仮定しません。

収集者の署名が保護するのは収集後の記録であり、それだけでAzure由来、完全性、操作権限は確立しません。
同じ侵害された運用者が管理する別名の鍵だけでは、独立した保管は成立しません。
XREFには、既存要件である各当事者の独立した記録とアンカーなどが必要です。
保護された原本と、公開用に情報を減らした版には、別々のアクセス・保存方針が必要です。
一度も観測されなかった操作を、後から収集やハッシュで復元することはできません。

予防、資格情報の失効、実行時の強制には、それぞれの制御と測定が必要です。
既存実験、固定証拠、規範仕様、リリース状態は維持します。
クラウド統合、独立再現、正式採択、本番運用可能性が成立したとの結果は示しません。
