# 消費者向けAIエージェントの商業関係と実行証跡

**状態：参考設計・未採用。確認日：2026年11月6日（日本時間）。**

[English](README.md) · [出典台帳](SOURCES.md)

このVSO提案は、消費者向けAIエージェントの代理関係、申告された商業関係、
推薦時の情報、認可された操作、データの保存・削除を検証するための証拠を整理する。
出典台帳では、報道で確認した政府のサイバー政策決定、一次資料で確認した予算措置、
既存のデータ管理注意喚起、有識者による消費者保護の議論を区別した。
以下の設計は、それらを踏まえたVSO側の提案であり、引用資料が要求する仕様ではない。

新たな採用済みプロファイル、規範フィールド、通信形式、認証結果、製品機能は定義しない。
本資料のために消費者エージェントの実装、新たな受入試験、AILEX本番環境の点検、
独立評価は行っていない。既存の実験は、それぞれの限定された検証範囲を持つ参考例である。

## 1. 検証する問い

利用者が委譲した仕事と、実際に観測された設定、申告された商業関係、利用者への提示、
外部操作を比較できる証拠を目指す。同時に、答えが得られない問いを残す。
有効な署名は、信頼する鍵に基づく申告の帰属を確認する手段になる。
利用者の利益に沿う行動だったことや、すべての利害関係が申告されたことは、それだけでは証明しない。

適用されるテナント、実行・要求ID、証拠発行者、鍵と役割の信頼根拠、ポリシーの版、
観測期間、収集範囲を明らかにする。申告と観測は区別して出典を残す。
モデルが後から生成した説明を、実行時の記録や非公開の内部推論そのものとして扱わない。

## 2. 証拠を関連付ける候補

以下はアプリケーション設計上の候補である。名称は説明用であり、VAP・DAP・LAPの
スキーマに追加されたフィールドではない。

| 検証対象 | 関連付ける証拠 | 解釈の限界 |
|---|---|---|
| 代理対象と委譲 | 利用者・組織、提供者・運用者の役割、依頼と制約、権限の範囲・期限・承認、本人性と鍵の信頼根拠 | 代理対象の申告だけでは、実際に誰の利益に資したかは証明しない。過去の権限付与は現在の権限を保証しない。 |
| 商業関係 | 申告主体、スポンサー・販売者・紹介関係、関係する報酬や手数料の方針、出典の版、有効期間、適用範囲 | 申告がないことは関係がないことを意味しない。署名は真実性や中立性の証明ではない。 |
| 目的と設定 | 利用者の制約、選択・順位付けポリシーの版、実効設定の観測、設定変更と判断の順序 | 宣言された目的や設定のハッシュだけでは、実際の最適化、公平性、設定の強制を証明しない。 |
| 入力と候補の範囲 | 実際に渡した資料、取得元・版・時点、取得できた候補集合、収集範囲、記録された除外 | 取得結果は市場全体ではない。包含証明は未取得・未収集の選択肢の検討を証明しない。 |
| 説明と承認 | 説明の正確な版・内容への参照、生成・表示・配信の観測、受領確認、操作に対応する承認 | 生成・表示・配信・受領確認は別の段階。それだけで理解や有効な同意を証明しない。 |
| 操作と結果 | 正確な送信先・アカウント・テナント、対象物・商品・金額、権限判断、要求、拒否・送信、受領証、確定結果・照合 | 要求、受理、実際の作用は異なる。真正な受領証でも、認可、公平性、未観測の迂回経路は解決しない。 |
| 保存と削除 | データ区分・目的、コピーの保存先と管理者、日付付き条件、起算事象・期限、例外、要求・ACK・範囲付き完了申告・別途の観測 | 期限経過や学習利用停止は削除完了ではない。稼働領域の申告はバックアップや下流コピーを包含しない。 |
| 収集と保管 | 観測点、除外、収集系の稼働状況、取得可能な記録、信頼根拠、存在する場合は独立管理された観測 | 同一運用者の別鍵・別プロセスは独立性を確立しない。事後の収集は実行前の収集を証明しない。 |

事業者による利害関係の申告と、その申告に対する評価者の判断は別の記録になる。
未申告の関係があっても、署名ログの内部整合性だけは成立し得る。
契約、突合、権限を得た独立した証拠などが必要な場合があり、暗号技術だけで
欠けた利害関係が発見されるわけではない。

外部操作は、実際に承認されたパラメータと比較する。提供者名の承認だけでは、
すべての送信先アカウント、内容、販売者、金額、権限まで承認されたとはいえない。
審査から実行までに設定・権限が変化すれば、以前の確認記録だけでは間のずれを防げない。
実行時に制約を強制する仕組みと、その評価を別途明らかにする必要がある。

## 3. 評価結果を分ける

将来の評価器は、次の観点ごとに証拠と未解決点を示す。
これらをまとめて「消費者に安全」「利益相反なし」という認定にしない。

| 観点 | 評価する範囲 |
|---|---|
| 記録の整合性・帰属 | 提供されたバイト列・証明が、明示した信頼条件で検証できるか |
| 対象範囲の充足 | 宣言した観測・証拠要件について、支持、矛盾、未解決を区別する |
| 商業関係の申告 | 誰が、どの関係を、いつ・どの範囲について申告したか。欠落・競合も残す |
| 説明の到達段階 | 証拠が支持する最も進んだ観測段階と、その間の欠落 |
| 認可の対応 | 該当する権限が、観測された正確な操作と時点をカバーするか |
| 操作結果 | 試行・受理・完了を分け、未確定の結果を残す |
| 保存・削除 | 適用条件と、別途裏付けられた削除段階・保存先・限界 |

全体の網羅性が不明でも、確認済みの矛盾は消えない。
例えば候補一覧が不完全でも、観測した操作が承認範囲から外れていれば不一致として残す。
逆に、取得できない記録があることを、その操作が発生しなかった証拠にしない。

## 4. データ管理とAILEXの点検順序

以下はAILEX等の法務AIサービスに対する点検提案であり、現行本番機能の説明ではない。
VSOとの代表者の共通性・商業関係は、[LAP紹介の開示](../legal-ai-profile/README.md#ailex-relationship-disclosure)
を参照する。

1. **データと受領先を棚卸しする。** 事件資料、チャット、添付、生成文書、検索・ベクトル領域、
   キャッシュ、運用ログ、バックアップを対象に、サービス・提供者・アカウント・テナント、
   再委託先、目的、責任者、保存条件を整理する。不明事項に仮の保存日数を割り当てない。
2. **保存ルールと対象を結ぶ。** 区分・保存先ごとに根拠、適用版、起算事象、期限を記録する。
   例外や保全指示は判断主体と見直し条件を持つ別項目にする。競合する条件は明示して解決し、
   最新の記載が過去の全コピーに適用されると仮定しない。法令・契約上の実際の期間は別途確認する。
3. **削除を範囲ごとに追う。** 要求、受領、範囲付き完了申告、観測を分ける。
   未確認のバックアップ、複製、キャッシュ、下流受領先を残す。復元・再生成時は新しいコピーと
   必要な削除対応を識別する。後日の存在だけで、以前の限定された削除申告を虚偽と断定しない。
4. **回答を検証できるようにする。** 実際に渡した根拠資料、取得できるモデル・設定の識別情報、
   申告された関係、専門家の確認、承認された正確な操作を関連付ける。
   取得不能な提供者情報は補作せず、出典の存在を内容の正しさと同一視しない。

機密性のある本文は、適切な保存方針とアクセス制御を持つ領域で管理する。
公開する証明の内容は必要に応じて最小化する。ハッシュは暗号化でも自動的な匿名化でもなく、
予測しやすい本文はダイジェストから推測され得る。コミットメントの設計では、推測可能性、
開示リスク、鍵の管理、後で必要となる検証を点検する。

コミットメントを残して本文を消去・利用不能にすると、後から実行できる検証も変わる。
その制限を記録する。鍵の破棄は、既に開示したコピー、別の平文、把握していない鍵の
バックアップを消去しない。署名付き削除受領証は、発行者の申告を記録するものであり、
全媒体の物理的消去や法令適合の結論ではない。
監査ログ自体も管理対象のデータ資産であり、アクセス・保存の方針が必要になる。
すべての会話の平文を永久保存することは、この提案の目的ではない。

## 5. 将来の点検ケース — 未実施

以下は将来の証拠仕様で確認する問いであり、実装済みのフィクスチャ、合格試験、
既存サービスの受入結果ではない。

| ケース | 想定される証拠 | 将来の評価で区別する点 |
|---|---|---|
| CA-01 | 推薦の署名はあるが商業関係の証拠がない | 記録の整合性が検証できても、商業関係の申告範囲は未解決のままにする。 |
| CA-02 | 観測したスポンサー優先設定が記録済みの利用者制約に反する | 署名が正しくても不一致を残す。因果関係・法的評価は別途必要。 |
| CA-03 | 取得候補はすべて検証可能だが、取得元の網羅性を裏付ける証拠がない | 取得集合の記録の整合性と、候補・市場の網羅性が未解決であることを分ける。 |
| CA-04 | 承認した販売者・商品・金額と、観測した要求が異なる | 過去の承認を、変更後の操作の認可として扱わない。 |
| CA-05 | 説明は生成されたが表示・配信の観測がない | 生成を配信に格上げしない。受領確認があっても理解は証明しない。 |
| CA-06 | 過去に有効だった委譲しかなく、十分に新しい状態証拠がない | 過去の記録と実行時の権限不明を分ける。状態記録の欠落は失効の証明でもない。 |
| CA-07 | 保存期限が経過し、ACKだけがあり、バックアップは未確認 | 期限状態、完了証拠、コピー範囲を分ける。 |
| CA-08 | 限定された削除申告の後で、同じデータが見つかる | 申告と後日の観測を残し、残存・復元・再生成を調べる。履歴を置き換えない。 |

## 7. 公開時の位置付けと追跡

資料の状態と未取得の一次文書は[出典台帳](SOURCES.md)に記載した。
今回の確認は、AILEXへの新たなAI固有義務、VAP/VCPへの政府推奨、調達資格、
認証購入の必要性を確立するものではなく、全省庁・全適用法令を網羅した調査でもない。

次の確認対象は、緊急対策パッケージの最終本文、消費者委員会の議事録や正式提案、
そして製品改善を主張する前の、権限を得た実環境のデータ経路点検となる。
将来の実証には、明示的な証拠仕様、プライバシー・信頼の境界、上記ケースの試験が必要。
この文書によって定期監視のジョブは作成されない。
